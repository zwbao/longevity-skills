# 产品合同与可行性

1. 用户提供一次原版 EMFRA 评估中第 1、2、5、6、7、11、12、15、19 项尚未反向计分的 0、1、2 分，以及实足年龄和是否已有医生确诊痴呆。
2. 技能已固定公开补充 R 文档表 64 的全部 18 个权重、原始条目编号和分因子反向计分规则；运行无需公开研究数据库，也不要求用户寻找补充材料。
3. 报告只计算两个独立因子的描述性分数并解释方向，不算总分、诊断、风险概率、临床分档、个人变化或治疗收益。

流水线已授权按这些边界构建，无另加确认步骤。方法名为 EMFRA factor scores。

测试按表 64 的顺序 [1,2,5,6,7,11,12,15,19] 输入以下原始向量：

## 输入与产品选择

- 只接收整数原始分数，单位 `score`，无需其他单位换算；`accept` 为空，不添加不确定的 LOINC。别名包括作者原始列名和明确的 EMFRA 中英文评分名称，避免与原始握力公斤数混淆。
- 缺项、错误单位、非有限数、分数小数、冲突重复项、人群条件缺失均退出 3；用 skillkit 解析并生成 problems.json。不会用零填补。
- 年龄至少 65 岁来自研究入选标准；120 岁仅为产品输入合理性上限，不是研究切点。实际样本范围为 65–99 岁，超过 99 岁仍给描述性数值并提示外推。
- 痴呆诊断史必须显式确认，已有诊断者不计算；不要求用户通过 MoCA 或本工具证明“没有痴呆”。性别可选，不改变公式。
- 不提供总分。两个因子各使用全部九项，包括较小的交叉权重；反向项集合不同，不能先统一反向再计算。
- 不提供 `--targets` 或 levers.json：这是尚未支持个人变化监测的描述性量表，不是可据此设定治疗目标的风险模型或时钟。小的交叉权重也不能解释成因果干预方向。
- 报告只描述因子方向，不用人群四分位数分个人档，不将 SEM、MDC95 或群体相关系数作为个人精度或疗效。
- 每份成功/失败报告均先放论文卡片，保留同一句边界；失败时覆盖已有结果为 null，成功时删除上次 problems.json。
