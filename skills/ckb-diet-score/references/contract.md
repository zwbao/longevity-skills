# 产品合同与可行性核查

1. 用户提供过去 12 个月五类食物的通常每周食用天数，可另给年龄、研究性别分层和部分食物的目标频率。
2. 技能维护者从原文及补充材料核对并固化评分规则和 HR；运行时不取队列原始数据，不让用户找论文、附录或数据库文件。
3. 报告计算逐项得分、总分、论文分档及该档对应的调整后人群 HR 和印出的 95% CI，允许比较用户目标情景；不计算个人死亡概率、完整生活方式总分、个人寿命或因果收益。

这是流水线已授权的饮食评分范围。所有需要的常数均已在编码前核实，未拟合、反推或从记忆补常数。

## 计算合同

来源：正文 Methods 的 Definition of low-risk lifestyle、表 1 饮食脚注、附录 S3 饮食脚注。

| 输入（通常食用天数/周） | 得 1 分条件 | 其他合法输入 |
|---|---|---|
| 新鲜蔬菜 | 每天，即 7 天 | 0 分 |
| 新鲜水果 | 每天，即 7 天 | 0 分 |
| 红肉 | 1–6 天，包含两端 | 0 分 |
| 豆类 | 至少 4 天 | 0 分 |
| 鱼 | 至少 1 天 | 0 分 |

五项相加为 0–5 分；4–5 分为论文低风险饮食组。查表档为 0–1、2、3、4、5。合并表使用 Table 1；male 使用 S3 p16；female 使用 S4 p18。所有表均保留全因、心血管病和癌症三个结局的 HR、CI 下限、CI 上限。不会混入 Table S7 的 Fine–Gray 亚分布 HR，也不将多个 HR 相乘。

单位采用仓库已有的 `d`，表示固定一周内食用的天数，键名明确 `days_per_week`。不存在可安全声明的其他单位换算：次数不能等同食用天数，小时不能等同进食日，克数不能变成频率，因此 `accept` 为空且不填 LOINC。平均食用天数直接按原文数值条件比较，不取整、不插值；每日必须为 7。6.5 天不满足红肉的 1–6 天条件，不擅自重构问卷分类。若用户只能给模糊类别，应先确认类别是否完全落在阈值同一侧，不能自选中点作为真实测量。

性别默认 pooled，明确传入 male/female 才使用分层表。年龄为可选上下文；18–110 岁只是软件防错范围，研究人群为入组 30–79 岁。年龄外推会在报告警示，输入不更改原表数字。病史没有在接口收集，报告明确未核实，主分析排除基线冠心病、脑卒中及癌症。

0–1 档打印的是 `1.00 (Referent)`，没有 CI；代码为 HR=1，CI=null，不把空区间改造成 [1,1]。其他区间完全照原文两位小数保留，包括跨 1 的区间。

## 复现层级

先写 `tests/test_manifest.py`，再写预设和计算代码。原文表格已经给出输入饮食档和输出 HR，可以直接复现查表方法：

- Table 1：输入档 0–1、2、3、4、5，逐一核对三结局及 CI；例如 5 分档的三列为 `0.74 (0.65-0.85)`、`0.62 (0.49-0.80)`、`0.80 (0.64-0.99)`。
- Table S3 / S4：各自核对 5 分行，男女不互换。
- 验证为精确匹配印出的两位小数；不是在个体随访数据上重拟合 Cox 模型。`validation.quote` 逐字列出被测表格单元格，换行分隔被选取的单元格，不包含旁边未测试的死亡人数列。
- 频率输入的端到端测试使用规则边界构造输入：7、7、1、4、1，五项各得 1 分，总分 5，再核对表 1 的 5 分行。这是依据印出的逐项规则设计的合成格式样例，不声称论文报道了这名受试者。
- 额外验证输入拒绝、报告边界和目标情景，不能用这些软件测试冒充论文的预测示例。

## 目标情景与不计算的内容

`levers.json` 遵循 `longevity-levers/1`，包含 current、sensitivity、levers 及可选 targets。输入是阶梯评分，敏感度列出每项单独增减一天（截断到 0–7）时的实际步长、输出和差值，不报告虚假的连续导数。目标只来自用户；同时改变多个项目与各自改变分别重算，因此不把各单项 HR 差相加。没有估计目标差的置信区间，因为论文没提供这些比较需要的协方差。

完整生活方式总分、扩展生活方式分数、慢性呼吸病结局和生命表不在此合同内。饮食部分不需要身体活动的年龄性别分位数阈值。用饮食记录无法确定其余生活方式因素；不能拿“五项食物都得分”代替“五项生活方式都低风险”。生命表还需年龄性别分组的 CNHS 加权频率、对应 GBD 死亡率及外推拟合常数；本文提供了方法及若干汇总图表，未在所读文件中给出全部可运行输入，不重建这些缺项。任何生命表结果都不应包装成个人剩余寿命。
