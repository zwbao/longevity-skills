# 本人的坐标表

CSV 三列表头为 `item,value,unit`。每个时间戳开始一帧，其后八行覆盖同一侧腿四个标志点。
例如下面**仅展示一帧的字段排布**，数字为空，不能作为可计算示例：

```csv
item,value,unit
time_s,,s
hip_x_cm,,cm
hip_y_cm,,cm
knee_x_cm,,cm
knee_y_cm,,cm
ankle_x_cm,,cm
ankle_y_cm,,cm
midfoot_x_cm,,cm
midfoot_y_cm,,cm
```

随后紧接下一帧的 `time_s` 及八个坐标，依此类推。所有值须来自本人的测量。
助手可以转换用户已有的宽表，但不能用演示数据替代缺项。
时间须严格递增且等间隔，整份文件只包含一个完整的同侧离地至再次离地前的周期。
同一帧坐标须具有相同原点、标定和方向；x 沿行走前方、y 向上。
镜头移动、未标定像素、透视变化、跑步机和转身需要不同处理，不属于此入口。

`midfoot` 指足中部标志点，不能从跟骨或脚趾坐标重命名而来。
人体视频中的髋、膝、踝和足中部必须已由姿态追踪人员核查。
本脚本既不运行姿态识别网络，也不读取原视频或原始 DLC 多行表头；
用户已有的追踪表应由助手转换成此格式，必要的标定和周期信息由提供者补齐。

别名及精确换算因子由 `skill.json` 管理。坐标接受 cm、mm、m；时间接受 s、ms。
没有疾病专用 LOINC 被用于这些自定义二维标志点。
